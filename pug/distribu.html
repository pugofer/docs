More on Distributaries

0.1. 1. Mathematics

Not merely “more discrete math,” but:

  • algebra
  • logic
  • probability
  • statistics
  • type theory
  • category theory, for the adventurous

This is perhaps the most natural distributary from the equational/Platonic side of Pug.

0.2. 2. AI / ML / Data

This is now unavoidable.

But I would not frame it as “learn Python + PyTorch.” The interesting continuation is:

programming → computation → data → models → learning

A Pug student who has learned to think in functions, values, transformations and equations has a rather good conceptual preparation for functional aspects of ML.

And there's a particularly nice pedagogical point: the student discovers that “programming” need not mean specifying every step of a procedure. That's an important bridge from functional programming to machine learning.

0.3. Formal methods

This one is very natural and I think you are currently missing it. Pug's:

types → equations → equational reasoning → explicit semantics

can lead toward:

  • theorem proving
  • model checking
  • specification
  • verification
  • proof assistants
  • dependent types

So:

Pug → Agda / Idris / Lean / Coq / formal methods

is a much more intellectually significant distributary than simply “learn OCaml.”

And it connects directly to your philosophical maturity idea.

0.4. Programming languages / language implementation

Another obvious one, especially because Pug is deliberately small.

A student may naturally become interested in:

parsers → interpreters → compilers → type systems → semantics → language design.

This is actually one of Pug's strongest natural distributaries because the student has been given a language small enough to understand rather than merely use.

0.5. Systems / hardware

I'd include this, surprisingly.

A student who has learned:

this expression denotes X; the machine eventually evaluates it

may become curious about the other side:

What actually happens when it runs?

Then:

  • C
  • assembly
  • operating systems
  • architecture
  • compilers
  • embedded systems
  • GPUs

And in the AI age, this becomes particularly interesting because AI has made the hardware/software boundary newly visible: accelerators, memory bandwidth, tensor operations, distributed systems, etc.

0.6. Data / information

This is related to ML but conceptually distinct.

A student might go:

values → structures → data → databases → information → information theory.

SQL, databases, data modelling, compression, information theory, data engineering — these aren't merely “AI preparation.”

This is especially interesting given your friend's five CS lineages.

0.7. So I might make the distributary map

Not as a prescribed curriculum, but as a fan-out:

Pug

→ Haskell / functional programming → mainstream programming → PL / compilers / semantics → formal methods / proof → mathematics / logic → AI / ML / data → systems / hardware → philosophy

And perhaps artificial intelligence is not the final destination but one of the great modern intersections of several of these. That fits your earlier five-lineage idea beautifully:

  • Automata → systems / hardware
  • Computation → algorithms / complexity / PL
  • Languages → PL / compilers
  • Logic → formal methods / theorem proving
  • Information → data / ML / AI

Then philosophy sits above or across them, asking what all these things are and what assumptions make them intelligible.

1. Destination?

Students are human beings (still… AFAIK!) The fates of students are written in the stars (or their genetic code… or their parental demands or love life or……..)

Pug doesn't prescribe a destination; it gives an enjoyable+illumintating interlude in the students' life-trajectory

A good introductory language leaves many intellectual doors open, rather than being a lathe to carve students into (pseudo-)masters of the next language in the syllabus.

And in the AI age, that means the “next step” might be Haskell, Lean, CUDA, statistics, databases, compiler construction, machine learning, philosophy — or ordinary Python.

The test is not whether the student gets a job but whether the student carries the habits of thought and intellectual pleasure with them.
